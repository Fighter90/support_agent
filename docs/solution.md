# ИИ-агент поддержки store.softline.ru — описание решения

Хакатон «ИИкузница» (Софтлайн Решения), трек «Клиентские сценарии», задача «Агент поддержки».
Автор: Емельянов Сергей. Стенд: https://methodagent.ru · Кабинет менеджера: https://methodagent.ru/manager · Репозиторий: https://github.com/Fighter90/support_agent

## 1. Задача и результат

Клиенты store.softline.ru часто пишут в чат, чтобы выбрать продукт, и на это уходит время менеджеров. Агент закрывает эти обращения в веб-чате сайта:

| Требование заказчика | Источник | Как реализовано | Статус |
|---|---|---|---|
| Сценарий 1: клиент знает продукт — сверить версии, предложить вариант, при нехватке данных уточнить | ТЗ (презентация, слайд 3) | `search_catalog(scenario=known_product)` → `get_product_variants(group_id)`; варианты по `group_id` фида; вопросы о числе пользователей, сроке, типе организации, продлении | Реализовано |
| Сценарий 2: клиент не знает решения — выяснить требования и подобрать продукт | ТЗ | Промпт задаёт до 3 вопросов (задача, пользователи, тип организации, отечественное ПО, бюджет), затем `search_catalog(scenario=need_selection)` и 1–2 варианта с обоснованием | Реализовано |
| Ответы на вопросы по сведениям о продуктах и покупке | ТЗ | RAG: `search_knowledge` по базе знаний (32 статьи: «Оплата и доставка» store.softline.ru + FAQ по перепискам) и данным фида | Реализовано |
| Российский аналог | Пример заказчика | Фильтр `only_domestic` по полю фида «Номер записи в реестре отечественного ПО» (1 208 позиций), агент называет номер записи | Реализовано |
| КП после согласия клиента (по шаблону) | ТЗ (доп.), ответы организаторов: «КП и счёт должны формироваться автоматически» | `create_quote` → форма реквизитов → PDF по «Шаблону КП ПАО Софтлайн» → подтверждение менеджером | Реализовано |
| Интерфейсы клиента и менеджера, передача сложных случаев | Ответы организаторов | Чат `/`, кабинет `/manager`: очередь эскалаций с резюме агента, ответ клиенту в его чат | Реализовано |
| Позиции без цены — уточнение у менеджера | Чат задачи | Агент не называет цену, если её нет в фиде; инструмент `escalate_to_manager(reason=price_on_request)` | Реализовано |
| Логирование всех вопросов и ответов | Чат задачи | Таблицы `messages`, `tool_calls`, `llm_calls` (токены, стоимость, задержка); журнал в кабинете | Реализовано |
| Пополнение базы знаний, дообучение на ответах менеджеров | Ответы организаторов, чат задачи | Ответ менеджера с отметкой «в базу знаний» становится статьёй RAG — агент отвечает сам в следующий раз | Реализовано (через RAG, без дообучения весов) |
| Каталог обновляется автоматически (фид Mindbox), раз в сутки достаточно | Чат задачи | Фоновая загрузка `https://store.softline.ru/feeds/Mindbox.yml.gz` раз в 24 ч, атомарная подмена БД каталога | Реализовано |
| Счёт на оплату | Ответы организаторов | Агент формирует КП; счёт выставляет менеджер (API 1С/CRM не предоставлены) | Не реализовано |
| Каналы «почта» и «телефон» | Ответы организаторов: «достаточно веб-чата» | — | Не требуется |
| Интеграции с API магазина, CRM, 1С | Ограничение ТЗ: «не предусмотрены» | — | Не требуется |

## 2. Архитектура

```
Клиент (браузер) ── /api/chat ──►  FastAPI ──► маскирование ПДн ──► Агент (цикл function calling, ≤ 6 шагов)
                                      │                                   │        ▲
Менеджер (браузер) ─ /api/manager ──► │                                   ▼        │
                                      │               GigaChat 2 Max (РФ) → резерв YandexGPT Pro (РФ) → mock
                                      ▼
             SQLite: catalog.db (136 040 позиций, FTS5) · app.db (диалоги, эскалации, КП, база знаний, журнал)
             Фоновая задача: фид Mindbox.yml.gz раз в сутки → пересборка catalog.db
             Генератор КП: HTML-шаблон → PDF (WeasyPrint)
Всё на одной ВМ в РФ (Timeweb Cloud), Docker Compose: app + Caddy (HTTPS Let's Encrypt)
```

**Инструменты агента**

| Инструмент | Что делает | Откуда данные |
|---|---|---|
| `search_catalog(query, scenario, only_domestic, org_type)` | Продуктовые линейки по запросу: название, вендор, класс, цена «от», число вариантов, реестр ПО | Фид, FTS5 + bm25 |
| `get_product_variants(group_id, users, term, org_type, license_type, text)` | Все версии/редакции линейки с ценами и параметрами, отличия между ними | Фид (`group_id`, `param`) |
| `search_knowledge(query)` | Статьи базы знаний | data/kb + ответы менеджеров |
| `create_quote(items[offer_id, quantity])` | Черновик КП; цены и НДС считает код, не модель | Фид |
| `escalate_to_manager(reason, summary)` | Передача менеджеру с резюме и причиной (8 категорий) | — |

**Защитные механизмы качества**
- *Проверка цен.* Каждая сумма в ₽ в ответе сверяется с ценами, которые вернули инструменты (допускается цена × количество). Неподтверждённая цена → модель переписывает ответ; повторная ошибка → цена заменяется на «уточнит менеджер».
- *Цены в КП* берутся из каталога кодом; позиция без цены или недоступная в КП не попадает.
- *Отказоустойчивость.* GigaChat → YandexGPT → детерминированный режим без модели (поиск по каталогу и базе знаний, эскалация).
- *Prompt injection.* Текст клиента и результаты инструментов помечены в промпте как данные; агент не меняет правила по просьбе клиента; доступ к кабинету — только по JWT.
- *Ограничение частоты:* 40 сообщений / 10 минут с IP, 5 попыток входа в минуту.

## 3. Защита данных, 152-ФЗ и трансграничная передача

1. **Трансграничной передачи нет.** GigaChat (ПАО Сбербанк) и YandexGPT (Яндекс) обрабатывают запросы на серверах в РФ; зарубежные модели (OpenAI, Anthropic и др.) в работе агента не используются. Уведомлять Роскомнадзор о трансграничной передаче (ст. 12 152-ФЗ) не требуется.
2. **Локализация (ч. 5 ст. 18 152-ФЗ).** Сервер приложения и база диалогов — в Timeweb Cloud (РФ). Персональные данные граждан РФ записываются и хранятся только в РФ.
3. **Минимизация (ст. 5).** Модели для подбора ПО персональные данные не нужны: до отправки в LLM ФИО, телефоны, e-mail, ИНН/ОГРН, номера карт и паспортов заменяются метками `[ТЕЛ_1]`, `[EMAIL_1]` (модуль `pii.py`). Соответствие меток хранится только в нашей БД и подставляется обратно лишь в интерфейсе.
4. **Реквизиты для КП мимо модели.** Название, ИНН, КПП клиент вводит в отдельную форму — данные идут прямо в генератор КП.
5. **Доступ.** Кабинет менеджера — по логину и паролю (JWT, срок 72 ч), HTTPS, секреты только в `.env` на сервере (не в репозитории).
6. **Для промышленной эксплуатации:** корпоративный договор GigaChat API с поручением на обработку ПДн (ч. 3 ст. 6), согласие на обработку ПДн в виджете чата, политика хранения логов (например, 1 год) — эти пункты оформляются юристами Софтлайна.

Использованные данные задачи (переписки, фид) — обезличенные или публичные; переписки хранятся вне репозитория (`data/raw` в `.gitignore`).

## 4. Выбор моделей

| Критерий | GigaChat 2 Max (основная) | YandexGPT Pro 5.1 (резерв) | Зарубежные (GPT, Claude) |
|---|---|---|---|
| Серверы и 152-ФЗ | РФ, без трансграничной передачи | РФ | Трансграничная передача, уведомление РКН, риски блокировки |
| Function calling | Есть (`functions`, `function_call`) | Есть (OpenAI-совместимый API) | Есть |
| Русский язык, термины лицензирования | Сильный | Сильный | Сильный |
| Цена, ₽ за 1000 токенов с НДС | 0,65 | 0,80 | Выше при оплате через посредников |
| Оплата юрлицом в РФ | Договор, ЭДО | Yandex Cloud | Затруднена |

GigaChat 2 Max выбран основной моделью: он дешевле, на русских бенчмарках сильнее младших моделей линейки (ruMMLU 0,80 против 0,77 у Pro), а function calling у него зрелый. YandexGPT подключён через тот же адаптер как резерв при недоступности или превышении лимитов. GigaChat 2 Lite (0,065 ₽) рассматривался для простых FAQ-вопросов — это оптимизация для масштаба 500 обращений в день (см. экономику).

**Почему не дообучение.** Каталог меняется каждый день (цены, наличие), а 987 переписок — это вопросы клиентов без эталонных ответов менеджеров. Дообучение «зашило» бы устаревшие цены в веса и требовало бы размеченных ответов. Поэтому используется RAG: актуальный каталог и база знаний подаются модели через инструменты, а ответы менеджеров пополняют базу знаний без переобучения.

## 5. Как использованы данные задачи

| Материал | Как использован |
|---|---|
| Каталог (фид Mindbox.yml, 136 040 предложений, 9 311 категорий) | Основа поиска и цен. `group_id` = продуктовая линейка (сверка версий); параметры «Тип организации», «К-во пользователей до», «Срок действия», «Тип лицензии», «Реестр ПО» — фильтры уточняющих вопросов. 44 601 позиция доступна с ценой; остальные — «цена по запросу» и эскалация |
| Обезличенные переписки (987 обращений, 9 категорий) | 1) Тестовый набор для оценки маршрутизации (eval/run_eval.py); 2) Источник типовых вопросов для синтетического FAQ (data/kb/faq_support.md — синтез разрешён организаторами); 3) Правила эскалации по категориям: скидки, госзакупки, follow-up по заказу |
| База знаний (документ со ссылками) | Страница store.softline.ru/delivery_info разобрана на 19 статей (scripts/build_kb.py); docs.softline.com содержит разделы без статей о покупке — не использована |
| Формат КП («Шаблон КП ПАО Софтлайн») | Воспроизведён один в один: шапка с адресом, «Куда», таблица «Артикул · Наименование · Кол-во · Цена · Сумма · В т.ч. НДС», условия, подпись |
| Сайт store.softline.ru | Ссылки на карточки товаров в ответах, статьи «Оплата и доставка» |
| Брендбук Softline | Цвета логотипа (#A20D32, #A7A8AA), логотип в чате, кабинете и КП |

## 6. Качество

Оценка на обезличенных переписках: см. `eval/report.json` и раздел «Метрики» в `docs/description.md` (маршрутизация, полнота эскалаций, срабатывания проверки цен, задержка, токены и стоимость одного запроса). Модульные тесты: `pytest backend/tests` (маскирование ПДн, проверка цен, загрузка фида, поиск, база знаний, сквозной диалог, КП).

## 7. Запуск и состав поставки

```
cp .env.example .env            # ключ GigaChat, пароли кабинета
docker compose up -d --build    # app + Caddy (HTTPS для methodagent.ru)
# при первом старте каталог загружается из фида автоматически (~1 мин)
pytest backend/tests            # тесты
python eval/run_eval.py --n 60  # оценка на переписках
```

## 8. Использованные наработки и компоненты третьих лиц

- **Собственная наработка автора — methodAgent** (https://github.com/Fighter90/methodAgent, GPL-3.0): перенесены и адаптированы схема настроек (pydantic-settings), подход к HTTP-клиенту LLM без SDK, JWT-авторизация, многостадийный Dockerfile, каркас React + Vite. Предметная логика, агент, поиск, КП и интерфейсы написаны в ходе спринта.
- Библиотеки: FastAPI, Uvicorn, Pydantic, httpx, lxml, PyJWT, WeasyPrint, openpyxl, React, React Router, Vite, lucide-react (лицензии MIT/BSD/Apache-2.0); Caddy (Apache-2.0); SQLite (public domain).
- Модели: GigaChat 2 Max (Сбер), YandexGPT Pro 5.1 (Яндекс) — по API.
- Инструменты разработки: Claude Code (Anthropic) — ассистент программирования.
